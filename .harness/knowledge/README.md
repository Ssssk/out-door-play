# 工程第二大脑

本目录保存可复用的开发经验和运行知识。它不替代 `wiki/` 的当前事实，也不替代 `changes/` 的变更过程。

## 分类

| 目录 | 内容 | ID 前缀 |
|---|---|---|
| `inbox/` | 尚未验证的临时记录 | `KB-INBOX` |
| `solutions/` | 已验证的问题解决方法 | `KB-SOL` |
| `incidents/` | 生产事故与复盘 | `KB-INC` |
| `decisions/` | 架构决策记录 | `ADR` |
| `patterns/` | 推荐模式 | `KB-PAT` |
| `anti-patterns/` | 已证实应避免的做法 | `KB-ANTI` |
| `runbooks/` | 可执行排障和运维手册 | `KB-RUN` |

所有正式记录必须从 `templates/` 复制并登记到 `index.yaml`。先使用 `knowledge-retrieval` 检索，解决后使用 `knowledge-capture` 沉淀。未验证内容保持 `draft`；过期内容标记 `deprecated`，不要删除历史。

不得保存 Secret、Token、完整个人信息、未脱敏生产数据或无权限传播的漏洞细节。

## 个人经验与 Skill 的吸收路径

导入个人经验包时使用 `experience-assimilation`，不要把整个 Skill 目录直接复制进本目录。按内容的真实职责拆分：

| 内容 | 去向 | 例子 |
|---|---|---|
| 长期不可违反且经过批准的红线 | `rules/` | 客户端授权不能替代服务端鉴权 |
| 可重复执行的完整作业流程 | `skills/` | 多端兼容验证、经验吸收 |
| 当前已经生效的项目事实 | `wiki/` | 当前支持的平台与版本 |
| 单次需求、决策和验证证据 | `changes/` | 某次微信小程序真机报告 |
| 可复用经验、模式、反模式和 Runbook | `knowledge/` | 冷启动 401 竞态、离线重放边界 |
| 与当前栈冲突、重复或无法确认来源 | 不生效；记录不采用理由 | PostgreSQL DDL 直接用于 MySQL |

吸收采用两阶段状态：

1. `inbox/draft`：已完成来源固定、拆分、去重和风险审查，但尚无当前项目的真实验证证据。
2. 正式分类/`verified`：在明确版本和平台上复现或验证，通过相关测试与 Reviewer 复核，并登记 `last_verified`、证据和失效条件。

源包的哈希用于证明“读的是哪一版”，不证明其中技术结论正确。任何候选知识被采用到设计或实现时，仍需结合当前代码、官方资料和目标端测试核验。
