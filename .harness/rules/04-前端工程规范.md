# 前端工程规范：uni-app + Vue 3 + Wot Design Uni

## 技术约束

- 使用 Vue 3 Composition API、`<script setup lang="ts">`、Pinia 和 Vite。
- UI 优先使用 Wot Design Uni 组件与主题变量；二次封装解决业务语义，不复制基础组件。
- 跨端代码必须遵守 uni-app API 与生命周期；使用浏览器 DOM、Node API 或平台专属能力前必须隔离并说明支持矩阵。
- `pages.json` 是页面、导航和分包事实来源；主包只保留启动与高频公共页面，业务低频页面进入合理分包。

## 推荐目录

```text
src/
  api/ components/ composables/ constants/ layouts/
  pages/ pages-sub/ stores/ styles/ types/ utils/
  App.vue main.ts manifest.json pages.json uni.scss
```

## 分层规则

- 页面负责路由参数、页面生命周期和用例组合，不直接散落请求细节。
- `api/` 负责服务端契约映射；`stores/` 只保存跨页面状态；短生命周期 UI 状态留在组件。
- composable 封装可复用的有状态逻辑；纯函数放 `utils/`。
- 业务组件不得通过全局单例暗中修改其他页面状态。

## 网络与状态

- 统一请求客户端处理 base URL、超时、认证、request-id、错误映射和取消。
- 401 刷新流程必须单航班化，失败后清理会话并避免无限重放。
- 重试仅用于明确幂等且瞬态失败的请求；写请求不得自动盲重试。
- 页面卸载后不应继续更新失效状态；搜索、联想等请求处理竞态和防抖。

## 交互与可访问性

- 所有加载、空状态、失败、权限拒绝和弱网场景必须设计。
- 破坏性动作二次确认；重复提交有禁用或幂等保护。
- 点击区域、对比度、字号、安全区、键盘遮挡和横竖屏按目标平台验证。
- Wot 组件主题通过变量集中定制，禁止页面内散落同义魔法色值。

## 跨端验证

至少验证需求声明的平台。涉及支付、登录、上传、定位、扫码、分享、推送、权限或原生插件时必须真机验证，H5 结果不能替代小程序/App 证据。
