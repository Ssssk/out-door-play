# UI/UX 与可访问性规范

## 设计基线

- 页面、组件、原型、视觉稿和文案必须记录来源与版本。
- 所有用户界面覆盖正常、加载、空、错误、无权限、禁用、成功和弱网状态。
- UI 优先使用 Wot Design Uni 与集中 Token，不复制基础组件或散落同义魔法值。
- 设计偏差必须记录原因、影响和 UI/UX Owner 结论。

## 跨端与响应式

- 明确 H5、微信小程序、App 等目标端、系统版本和设备范围。
- 验证安全区、键盘遮挡、横竖屏、窄屏、长文案、深链和导航栈。
- 登录、支付、上传、扫码、定位、分享和原生插件使用目标端/真机证据。
- H5 通过不得外推为小程序或 App 通过。

## 可访问性

- 关键操作具备足够触控区域、对比度、可读字号和明确文本。
- 状态不得只依赖颜色；错误提示与输入建立可理解关联。
- Web/H5 检查键盘、焦点和语义；支持环境检查屏幕阅读和减少动态效果。
- 偏差必须有 Owner、期限和风险接受，不得以用户假设静默跳过。

## Gate

UI/UX 与 accessibility 证据是前端验证和产品 UAT 的输入；设计变化返回设计 Gate，实现缺陷返回实现阶段。
