# API 与错误协议规范

## HTTP 约定

- 基础路径 `/api/v1`；破坏性变化通过新主版本或兼容迁移，不在原路径静默改变语义。
- 资源使用复数名词；HTTP 方法表达语义；操作型端点只在无法自然建模为资源时使用。
- 查询参数明确分页、排序、过滤和默认值；列表默认限制最大页大小。
- 时间使用 ISO 8601 UTC；金额使用最小货币单位整数或明确 Decimal 字符串，禁止浮点累计。
- ID 在前后端契约中统一为字符串，避免小程序 JavaScript 大整数精度风险。

## 标准响应

成功响应：

```json
{"data": {}, "requestId": "req_xxx"}
```

失败响应：

```json
{
  "code": "CART_STOCK_NOT_ENOUGH",
  "message": "库存不足",
  "details": [],
  "requestId": "req_xxx"
}
```

- `code` 稳定且可供客户端分支；`message` 面向用户或调用方；`details` 不暴露敏感内部信息。
- 正确使用 2xx、4xx、5xx；业务冲突通常使用 409，输入不合法使用 400/422，未认证 401，无权限 403。

## 幂等与并发

- 创建订单、支付、发券等关键写操作支持 `Idempotency-Key` 或业务唯一键。
- 更新资源需要并发保护时使用版本号/ETag 或业务条件更新。
- API 契约文件必须在代码前或同时更新，并以契约测试防止漂移。
