# TypeScript 与编码规范

## 编译与类型

- 前后端必须启用 TypeScript 严格模式；禁止以全局关闭严格检查解决局部问题。
- 禁止无理由使用 `any`、非空断言和双重类型断言；不可信输入先以 `unknown` 接收再验证。
- 对外 DTO、事件载荷、配置和存储边界必须有显式类型。
- 避免超大函数、布尔参数迷宫和隐式副作用；以业务意图命名。

## 命名

- 类型、类、组件：`PascalCase`；变量、函数、composable：`camelCase`；常量按项目 ESLint 约定。
- NestJS 文件使用职责后缀：`.controller.ts`、`.service.ts`、`.repository.ts`、`.entity.ts`、`.dto.ts`。
- Vue 组件文件使用 `PascalCase.vue`；页面目录使用短横线或项目既有统一形式。
- 事件采用过去式业务事实，如 `order.created.v1`，命令采用动词，如 `order.cancel.requested.v1`。

## 错误处理

- 不吞异常，不用空 `catch`，不把堆栈或内部 SQL 返回客户端。
- 业务拒绝使用稳定业务错误码；技术故障记录结构化日志并映射为安全响应。
- 异步调用必须明确超时、重试、取消和幂等边界。

## 代码质量

- Lint、格式化、类型检查在 CI 中确定性执行。
- 注释解释“为什么”和约束，不复述代码。
- 删除废弃代码，不保留注释掉的实现；临时兼容必须有移除条件。
