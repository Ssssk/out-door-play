# Redis 规范

## 使用边界

Redis 用于缓存、短期会话、限流、幂等记录、分布式协调和适合的数据结构，不作为缺少持久性设计的唯一业务事实来源。

## Key 规范

```text
<env>:<app>:<module>:<purpose>:<business-id>[:<version>]
```

示例：`prod:mall:cart:snapshot:user_123:v1`。禁止包含口令、完整 token、身份证号等敏感明文。Key 必须有所有者、数据类型、TTL、最大规模和失效策略。

## 缓存

- 默认 cache-aside：读 miss 回源并设置 TTL，写成功后删除或版本化失效缓存。
- TTL 加随机抖动避免雪崩；热点 miss 采用互斥回源或逻辑过期；空结果短 TTL 防穿透。
- 禁止无 TTL 的临时缓存；永久数据结构必须有容量和清理策略。
- 缓存错误不能把陈旧数据伪装成强一致结果；需要强一致时直接读取主存储。

## 并发与锁

- 优先使用数据库唯一约束、条件更新或原子 Redis 命令，分布式锁不是默认方案。
- 必须使用锁时包含唯一 token、超时、所有权校验释放、续期边界和失败处理。
- 锁保护的业务仍需数据库最终约束，防止租约过期造成并发写入。

## 运维

- 连接使用超时、重连上限和监控；阻塞型命令使用独立连接。
- 禁止在线执行无界 `KEYS`；使用 `SCAN` 也必须限速并评估影响。
- 监控命中率、内存、淘汰、热 Key、大 Key、连接和延迟。
