# AI Skill 与知识治理规范

## Skill 定位

`.harness/skills/` 中的 Skill 是可重复执行的工程作业规程，不是简介、提示词片段或授权凭证。Skill 必须服从 Rules、已批准 Change 和人工 Gate，不能自行扩大需求范围、执行生产操作或替代审批人。

## Skill 必备结构

每个 `SKILL.md` 必须包含以下章节：触发条件、不适用场景、前置 Gate、必读上下文、输入、执行步骤、技术约束、产物、验证与证据、停止与升级条件、禁止事项、完成定义。

技术 Skill 必须给出本技术栈的具体检查点，不得只写“遵循最佳实践”。步骤需要使新的执行者能够在不依赖聊天历史的情况下完成工作。

## 执行规则

1. 根据用户目标和 Change 状态选择最少但完整的 Skill 集合。
2. 开始前读取 Skill 声明的上下文，不得凭记忆假设仓库事实。
3. 按步骤执行并维护任务、契约、测试和证据之间的追踪关系。
4. 遇到停止条件立即暂停当前阶段，记录事实并回到对应 Gate。
5. Skill 的“完成”只代表该项作业完成，不代表 Change 自动获批。

## 知识分层

- `wiki/`：当前已经生效且经过确认的系统事实。
- `changes/`：单次变更的需求、决策、过程和证据。
- `knowledge/`：可检索的经验、故障、解决方案、模式、反模式和操作手册。

任何长期事实只能在 Change 生效后同步到 Wiki。未经验证的经验进入 `knowledge/inbox/`；验证后才能进入 solutions、patterns、runbooks 或 decisions。事故记录不得因修复完成而删除。

## 知识检索门禁

需求分析、影响分析、设计、编码、排障、测试、评审和发布前，必须按模块、技术栈、症状、错误码和相关 Change 检索知识库。采用知识记录时必须引用知识 ID，并检查状态、适用边界与 `last_verified`。

状态语义：

- `draft`：刚记录，尚未验证。
- `verified`：已有可复核证据。
- `deprecated`：曾经有效但已不适用于当前基线。
- `rejected`：已经证伪或确认不应采用。

## 知识沉淀门禁

满足任一条件必须沉淀：排障超过 30 分钟；同类问题第二次出现；发生线上事故；形成关键架构决策；发现高风险反模式；同一人工操作执行两次以上；Change 完成时产生可复用经验。

知识记录必须包含现象或上下文、触发条件、根因或决策理由、处理方法、验证证据、适用边界、无效方法、关联文件/Change、负责人和最后验证时间。不得保存密钥、Token、个人敏感数据或未经脱敏的生产数据。

## 外部与个人经验吸收

个人 Skill、旧项目规范、压缩包、聊天记录和外部文章属于“候选知识源”，不是当前 Harness 的自动权威。导入时必须执行 `experience-assimilation`，并遵循以下规则：

1. 固定来源路径、版本、文件哈希、读取日期和作者可确认性；来源不可追溯时仅可作为低置信度线索。
2. 先按最小知识原子拆分，再分别路由到 Rules、Skills、Wiki、Changes、Knowledge 或“不吸收”；禁止整包复制后整体生效。
3. 长期强制红线只有在与当前技术基线一致、风险理由明确且经过治理审批后才能进入 Rules。
4. 可重复作业流程进入 Skills；具体故障、经验、模式、反模式和 Runbook 进入 Knowledge；已生效项目事实进入 Wiki；一次变更证据留在 Changes。
5. 源包的结构校验、单元测试或自述“生产级”只能证明对应制品的有限属性，不能证明技术结论已在当前项目和目标端验证。
6. 未经当前项目证据验证的经验必须放入 `knowledge/inbox/`，状态为 `draft`；不得因多个来源互相引用就提升为 `verified`。
7. 与当前栈冲突的实现必须显式隔离。例如 PostgreSQL 的 `lock_timeout`、`CONCURRENTLY` 不能进入 MySQL Runbook，Vue 2/uView 指令不能进入 Vue 3/Wot Design Uni 主路径。
8. 时间敏感的安全、平台审核、SDK、浏览器和应用商店规则，使用前必须核对当时的官方来源，并记录查询日期。
9. 发现危险经验时保留为 anti-pattern 或吸收报告中的“不采用”结论，说明风险和替代方案，不静默删除导致后续重复踩坑。
10. 每个候选项必须定义晋级条件、Owner、复核期限和失效条件；完成真实 Change 验证后才允许移动到正式分类并更新索引。

来源内部声明与当前 Harness 冲突时，服从顶级契约、Rules、已批准 Change 和当前代码事实。吸收行为不授予修改生产、执行外部动作或绕过 Gate 的权限。
