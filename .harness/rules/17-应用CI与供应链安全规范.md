# 应用 CI 与供应链安全规范

## CI 强制阶段

active 项目必须执行：确定性安装、格式检查、Lint、TypeScript、单元、构建、契约、集成、E2E、安全和 Harness 校验。

- 锁文件与包管理器一致，禁止隐式升级。
- 强制命令不得使用 `--if-present`、`|| true` 或其他吞失败机制。
- 制品一次构建并绑定 SHA/digest，测试和发布复用同一制品。
- MySQL 以及当前 Change 实际采用的 Redis/RabbitMQ 使用隔离服务，测试结束可清理；未采用的基础设施明确标记 not-required 并由架构 Gate 说明理由。
- CI 输出机器 Evidence，包含 SHA、环境、命令、时间、退出码和报告。

## CI 权限

- Workflow 使用最小权限，第三方 Action 固定受控版本。
- fork PR 不得获取生产 Secret；CI 不得访问生产数据库或真实用户数据。
- 缓存仅用于加速，不能成为正确性依赖。
- 不稳定测试必须治理，不能无限重跑直到绿色。

## 供应链安全

- 依赖变化执行 Secret、SAST、SCA 和许可证检查。
- 发布制品生成 SBOM，并与最终镜像/制品 digest 对应。
- 容器检查基础镜像来源、非 root、最小能力、漏洞和签名。
- IaC 与 CI 检查危险权限、公开入口和 Secret 注入。
- P0/P1 阻塞发布；例外有独立批准、补偿控制和到期时间。

## 模板模式

本分发目录允许 `project-quality.json` 为 template；复制到真实项目后必须通过 `harness-adoption` 校准并改为 active。template 模式输出不能作为应用 CI 通过证据。
