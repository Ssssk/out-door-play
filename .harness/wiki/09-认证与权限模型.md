# 认证与权限模型

## 认证

当前未发现 Guard、JWT、Session 或微信 code 登录实现。`user/me` 和 `admin` 写接口不能视为具备生产认证。

已批准方向（尚未实现）：

- 移动端微信登录，服务端交换并管理会话/短期访问凭证；具体生命周期在身份 Change 中冻结。
- 管理端独立登录与会话撤销，不复用客户端“固定用户”。
- 登录/刷新端点限流和安全审计。

## 授权

采用 RBAC + 资源级策略：角色授予动作集合，策略进一步检查资源所有权、组织/租户和对象状态。

```text
subject + action + resource + context -> allow | deny
```

默认拒绝。前端可以按权限改善 UI，但服务端必须对每个受保护用例重新授权。管理端批量操作和敏感导出需要更高权限、理由和审计记录。

在该模型实现并验证前，管理写能力不得进入发布候选。
