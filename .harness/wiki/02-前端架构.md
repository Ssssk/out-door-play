# 前端架构

## 当前应用

- `apps/mobile`：uni-app Vue 3；页面位于 `src/pages`，API 在 `src/api/outdoor.ts`，公共请求/路由/地图/媒体能力在 `src/common`。
- `apps/admin`：Vue 3 + Element Plus；路由视图覆盖路线、榜单、城市、油价、用户、UGC、分析与报表。
- 2026-08-30 已修复 Admin typecheck，并新增 2 个响应协议测试；页面/权限测试仍待后续 Change 补齐。

## 目录与职责

```text
src/
  api/              # 按领域拆分的 API 函数与 DTO 映射
  components/       # 业务无关或跨页面组件
  composables/      # 可复用有状态逻辑
  pages/            # 主包页面
  pages-sub/        # 业务分包
  stores/           # 跨页面业务状态
  styles/           # tokens、主题与公共样式
  types/            # 稳定共享类型
  utils/            # 无副作用纯工具
```

## 数据流

目标数据流仍采用页面 → composable/use-case → API adapter → DTO/page model。现有代码应按垂直 Change 渐进调整，不进行无界目录搬迁。

## Wot Design Uni

- 建立统一 Design Tokens：品牌色、语义色、间距、圆角、字号、阴影和层级。
- 基础交互优先使用 Wot 组件；业务封装组件必须转发关键无障碍和事件属性。
- Toast/Message/Loading 由统一反馈服务管理，避免多页面并发关闭彼此的 Loading。

运营后台继续使用 Element Plus；不得把 Wot 组件用于 PC Admin，也不得让 Element Plus 进入 uni-app 包。

## 跨端策略

- 平台差异集中到 `common/platform`、能力 adapter 或条件编译边界。
- 页面不散布大量平台判断；无法统一的能力定义端口和平台实现。
- `pages.json` 与 manifest 变化纳入 Change，并验证目标端权限、分包和启动表现。
