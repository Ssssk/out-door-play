# 部署拓扑

## 当前本地环境

```text
apps/mobile dev/build
apps/admin Vite :5174
apps/api NestJS :3100
  -> Docker MySQL 8.4 :3307
```

当前没有生产 Ingress、API replica、Worker、Redis、RabbitMQ 或可观测后端。

## 当前授权测试服务器

```text
HTTPS 入口（80 -> 443）
  -> chumen-web-prod (Nginx :80/:443，官网与静态管理端)
       -> /v1/* -> chumen-api-prod (:3100)
                       -> chumen-mysql-prod (:3306，仅容器网络)
```

- 服务器为 Ubuntu Server 24.04 LTS，运行 Docker Engine 与 Docker Compose；宿主机无需单独安装 Node.js、MySQL 或 Nginx。宿主机安装了 Certbot 负责续期，宿主机 Nginx 服务已停用。
- `chumen-web-prod` 就是 Nginx 容器，生产配置从 `/opt/chumen/nginx/production.conf` 挂载到 `/etc/nginx/conf.d/default.conf`；证书从 `/opt/chumen/certs` 挂载，ACME challenge 从 `/opt/chumen/certbot-webroot` 挂载。
- `.github/workflows/deploy-production.yml` 仅允许 `main` 手动触发；普通 push 不自动部署。
- `.github/workflows/ci-component-release.yml` 监听 `main` 上 API、管理 Web、小程序和共享构建路径。它先用 `tools/ci/changed-components.mjs` 判定受影响组件，仅运行对应 CI；多组件变更固定按 API → 管理 Web → 小程序串行，前置失败阻断后置。该工作流只做质量构建与已批准的小程序体验版上传，不替代生产手动部署。
- 若提交说明包含 `[skip-miniprogram-experience]`，中央工作流仅跳过本次小程序体验版 Job；后端和管理 Web 仍按变更范围执行。该标记用于本地插件已经上传同一份代码、且明确不需要远程重复上传的场景。GitHub Runner 不读取开发机插件记录，因此没有标记时不会自动去重。
- 本地 `auto-work-tools` v1.12.0 提供“仅推送代码”和“推送并发布体验版”两种交付方式，并从仓库根目录 `.mini-publisher.json` 读取 Git remote、去重标记和小程序路径规则。组合模式只在完整待推送范围命中小程序路径时本地上传；上传成功且代码状态未变化后才 push 带标记的同一提交。不命中小程序路径时按普通 push 处理。
- 插件执行 push 前会 fetch 并验证远程目标分支是本地 HEAD 的祖先；不执行 pull、rebase、force push。远程领先、微信上传失败或上传后代码状态变化都会阻断 push。
- 工作流先在 GitHub Runner 验证 API/Web Docker 构建，再上传当前 SHA 源码，由测试服务器构建 SHA 镜像、执行 Prisma migration 并启动 Compose。
- 服务器代码部署只更新 API 与管理端 Web，不自动覆盖业务数据。
- 当前远程域名环境使用 `ADMIN_COOKIE_SECURE=true`；临时 HTTP 测试配置仅保留在文档示例中。

## 微信小程序体验链路

- `.github/workflows/deploy-miniprogram-experience.yml` 监听 `main` 上移动端、构建配置和上传工具的变更，独立构建 `apps/mobile/dist/build/mp-weixin`。
- 微信上传私钥只存放在 GitHub Actions Secret `WECHAT_MINIPROGRAM_PRIVATE_KEY`；AppID、robot 和 API 地址使用 Repository Variables，私钥文件不得进入 Git。
- `WECHAT_MINIPROGRAM_UPLOAD_ENABLED` 是 fail-closed 开关；只有安全风险获得明确接受后才设为 `true`，否则整个上传 Job 跳过且不会读取私钥。
- 工作流使用微信 `miniprogram-ci` 上传开发版本，并把当次体验预览二维码保存为 7 天 GitHub Artifact；这不代替微信平台的审核与正式线上发布。
- 微信体验版备注由 `tools/miniprogram-ci/describe-change.mjs` 自动生成，提交类型、摘要和变更范围统一转换为中文；无法翻译的英文摘要只保留中文类型，不会把英文原文写入备注。
- 小程序工作流采用双 Job：GitHub-hosted Runner 完成源码 checkout、依赖安装和构建；仓库级 `wechat-uploader` self-hosted Runner 只下载无密钥 payload、短暂注入上传私钥并调用微信，最后清理私钥和工作目录。
- `wechat-uploader` 运行在当前授权测试服务器固定出口，使用 UID `2001` 的专用非 root 账号，不属于 Docker 组；systemd 限制其读取 `/opt/chumen`、获取额外 capability 或访问 link-local 云主机 metadata。上传 Job 使用服务器预置、按官方 SHA-256 校验的 Node.js `22.23.2`。GitHub Actions run `34034184969` 已验证微信看到的出口为 `124.223.220.242`；该 IP 仍需由小程序管理员加入微信代码上传密钥 IP 白名单。
- `chumenliuliu.cloud` 的 DNSPod 根 A 记录已指向当前服务器，且 2026-09-12 已新增 `www A 124.223.220.242`；远程容器已提供官网根路径、`/admin/` 管理后台和 `/v1/` API，HTTP/HTTPS 首页、后台、健康检查和证书 SAN 已验证。腾讯云 ICP 备案控制台仍显示“未备案”时，不得宣称公安联网备案或微信真机请求已完成；正式请求还需微信公众平台 request 合法域名配置。

## 当前同步约定

后续变更先按 `KB-INBOX-012` 在本地 Docker 完成构建、迁移、启动和冒烟；通过后才提交、push 并部署测试服务器。数据库 data sync 是独立的高影响步骤，必须先核对 migration、备份和逐表精确计数，禁止绑定普通 push 自动执行。

生产域名/TLS、Secret 生命周期、自动备份、灰度、回滚、监控和正式发布 Gate 仍为 pending；本地或测试服务器结果不能作为生产 Operations Gate 证据。
