# 后端架构

## 当前模块化单体

NestJS 模块包括 health、cities、routes、fuel、user 和 admin。当前 Controller/Service 主要直接使用 PrismaService，尚未形成完整 API/Application/Domain/Infrastructure 分层。

## 四层结构

1. API：Controller、DTO、Guard、Presenter。
2. Application：Command/Query、用例、事务编排。
3. Domain：Entity、Value Object、Policy、Domain Event、Repository Port。
4. Infrastructure：Prisma Repository adapter；Redis、RabbitMQ 和外部 Client 只在批准的垂直 Change 中引入。

## 横切模块

- `config`：配置校验和 typed configuration。
- `observability`：日志、指标、Trace、request context。
- `database`：当前 PrismaService 与 Prisma Migrate。
- `cache`：尚不存在。
- `messaging`：尚不存在。
- `security`：认证、授权、限流和审计。

现有 `common` 只包含 request-id、统一响应与异常过滤。认证授权、配置 schema、结构化日志和 OTel 属于待补能力。
