> 状态：计划稿，`not-run`。Operations Gate 前须补齐值班人、联系方式与演练记录；本文件不含任何真实凭证或联系方式。

## 分级

| 级别 | 触发条件 | 处置 |
|---|---|---|
| P0 | 生产数据损坏、回填误改非目标行、收藏或分享大面积不可用 | 立即停止发布/回填、启用备份恢复、通知发布负责人与数据库 Owner |
| P1 | `scene=fish` 请求返回 422/500、旧小程序包白屏、钓鱼详情 5xx、配置保存大面积 409 | 回滚应用版本或降级兼容映射，阻塞后续发布 |
| P2 | 单个分类空态文案异常、后台筛选体验问题、非关键日志缺失 | 记录并进入下一迭代，不阻塞已通过 Gate 的发布 |

## 止血与回滚

1. 停止当前发布步骤与回填批次，保留现场日志、SQL 哈希与备份点。
2. 按 `release/rollback-plan.md` 选择可回滚项：应用版本回退优先，数据库保持 Expand 共存状态。
3. 确认旧包与新包在兼容期内仍可访问首页、列表、详情与分享。
4. 恢复后执行只读校验：影响行数、收藏完整性、分享详情 200、配置 revision 连续性。

## 值班与升级路径

- 发布窗口与观察期值班人、备份恢复执行人、产品/架构/安全决策人由 Operations Gate 指定，当前均未指定。
- 升级顺序：值班人 → 后端/数据库 Owner → 发布负责人 → 产品 Owner；涉及 P0/P1 时不得由主要实现者自行批准修复。
