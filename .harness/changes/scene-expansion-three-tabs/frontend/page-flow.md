# 前端页面流

## 目标平台

| 端 | 范围 | 目标端证据 |
|---|---|---|
| 微信小程序 | 首页 3 分类、卡片子类型标签、详情分流、分享直达 | 是（主目标端，体验版/真机） |
| H5（uni-app） | 同一实现，双端构建回归 | 是（构建与冒烟） |
| 运营后台 Web（Chrome） | 路线列表 3 tab + 二级筛选、表单、分类配置页 | 是（浏览器 E2E） |
| App | 不在本期支持矩阵 | `not-required` 由产品 Gate 裁决 |

## 页面/路由/分包变化

- 小程序**不新增页面、不改 `pages.json`、不改底部 `tabBar`**（DEC-E07）。
- 分享路径保持不变：`fishing-detail?spotId=`、`route-detail?routeId=`，保证迁移后链接可用。
- 后台路由不变，仍是 `/routes` 与 `/system-config/scene-tabs`；仅筛选与表单交互变化。

## 用户流程

1. 运营打开「路线列表」→ 默认「全部」→ 点「粗门玩玩」→ 出现二级「钓鱼/露营/打卡」→ 筛选列表。
2. 运营点「+ 新建玩玩路线」→ 选择子类型 → 填写对应字段组 → 保存 → 列表出现新记录。
3. 运营打开「系统配置 / 首页分类目录」→ 调整 3 个分类的名称/启停/排序 → 保存 → 小程序下次进入首页生效。
4. C 端用户进入首页 → 服务端配置可用时看到 3 个分类（配置不可用时降级到仅 `drive`）→ 切换分类 → 列表按 scene（+ subType）加载 → 点卡片按子类型分流详情。
5. C 端用户从聊天打开迁移前分享的钓鱼链接 → 仍进入 `fishing-detail` 并完整渲染。

## 加载、空、错、权限和弱网状态

| 场景 | 小程序首页 | 后台路线列表 |
|---|---|---|
| Loading | 用缓存立即渲染；无缓存时用本地兜底仅 `drive`，列表沿用既有 loading | `v-loading`，按钮禁用 |
| 空 | 「该分类暂无内容」引导，不白屏、不塌陷 | 「暂无符合条件的路线」 |
| 错误 | 配置接口 404/5xx/超时/损坏时静默降级到仅 `drive`（两层默认），不展示内置 3 项；列表错误展示重试 | 错误态 + 重试，保留筛选条件 |
| 无权限 | 公开读不涉及 | `route:read` 缺失跳 Forbidden；只读账号隐藏新建/编辑 |
| 弱网 | 超时回退，不重试风暴 | 沿用 15s 超时与统一提示 |
| 重复提交 | 配置请求去重 | 保存按钮禁用 + 服务端校验 |
| 卸载竞态 | `onUnload` 后不写回状态 | 离开页面不写共享状态 |

## 组件与主题

- 小程序沿用 `SceneTabs.vue` 的 CSS 变量与 70rpx 触控高度；不复制 Wot Design Uni 组件实现。
- 后台沿用 Element Plus 与现有 panel 样式；不新增 UI 依赖与设计 Token。
- 3 个 tab 与二级筛选保留 `role="tablist"` / `role="tab"` / `aria-selected`。

## 跨端差异和真机验证

- 不使用平台专属能力，无需条件编译；属性一律 camelCase props。
- 真机/体验版必须验证：3 个分类吸顶与安全区、`onShow` 生效、下拉刷新、钓鱼分享直达、空分类引导、弱网兜底。
- 后台必须验证：键盘可达、只读账号视图、409 冲突提示、恢复默认二次确认。
- 小程序改动须重新构建上传、审核并正式发布；服务器部署不改变手机端代码包。
