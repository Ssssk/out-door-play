## 指标与阈值

| 指标 | 阈值 | 采集方式 |
|---|---|---|
| 路线列表查询 P95 | ≤ 200ms（与既有列表基线一致） | 集成环境采样 + 压测报告 |
| 列表查询 P99 | 记录并对比基线，超出需说明 | 压测报告 |
| `MODIFY ENUM` 执行时长与锁等待 | 无长事务阻塞，记录数值 | 演练 MySQL `performance_schema` / 慢日志 |
| 回填批次时长、复制延迟、磁盘占用 | 记录数值并评估分批或在线变更 | 演练环境指标 |
| 兼容映射额外开销 | 不引入 N+1 或无界查询 | 代码评审 + SQL 计数断言 |

## 场景

1. 演练环境使用与生产同版本 MySQL/InnoDB，`discoveries` 行数与生产同量级（TASK-E02 给出实际行数评估）。
2. Expand 阶段执行 `ALTER` 增加 enum 值、`sub_type` 列与 `(city_code, scene, sub_type)` 索引，记录锁与复制延迟。
3. Migrate 阶段按幂等条件 `WHERE scene='fish' AND sub_type IS NULL` 分批回填，记录每批行数与耗时。
4. 回填期间并发读取列表接口，采集 P95/P99 与错误率。
5. 对比新增索引前后的执行计划，确认无隐式全表扫描。
