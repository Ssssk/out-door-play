# 回滚计划

## 触发条件与决策人

- 触发条件：首页出现 0 个分类或分类渲染异常；列表接口 5xx / 错误率上升；配置接口持续不可用；隐藏场景详情或分享链接打不开；运营误配导致业务分类大面积不可见。
- 决策人：发布负责人 / Incident Commander（Q-004 指定）；配置层止损可由运营在授权范围内执行「恢复默认」，代码层回滚需发布负责人批准。
- 停止条件：指标恢复观察窗口内的基线，且产品 Owner 确认 C 端可见行为回到预期。

## 应用回滚

- **第一优先：配置层前向修复**。在后台点击「恢复默认」把配置改回 DEFAULT（仅 `drive` 启用），用户下次进入首页即恢复；无需发版、无需数据库回滚。
- API revert：把服务端回退到上线前版本。新接口消失后，新小程序包按 `AC-CFG-011` 回退内置 DEFAULT，行为与旧版一致；残留的 `scene_tabs` 配置行对旧代码无副作用（旧代码不读该键）。
- 后台 revert：移除新菜单/路由/页面后，运营不再能修改该配置；已有配置行保留，不影响 C 端。
- 小程序包：**不可瞬时回滚**。已发布的小程序代码包需重新提交版本才能撤回；因此 DEFAULT 与旧版行为一致是唯一可靠安全垫（DEC-010），任何时刻都不应把默认配置改成与旧版不同的内容。

## 数据库回滚/前向修复

- 不执行数据库回滚、不执行 `DELETE`、不还原备份、不重置 `updated_at`。
- 配置损坏或误配统一用「恢复默认」前向修复（`updateMany` 条件更新，`revision` 递增，可审计）。
- 若数据库整体需恢复，按既有备份流程执行；恢复后记录不存在时读取端返回 DEFAULT，首页仍可用（`backend/migration-plan.md`）。

## Redis Key/缓存格式处理

- 不适用：DEC-008 与 ADR-006 决定不引入 Redis，服务端无配置缓存。
- 小程序端 `listCacheKey` 含 `revision`：回滚配置后 revision 递增，旧缓存 key 自动不再命中，无需清理脚本。

## RabbitMQ 事件与消费者兼容

- 不适用：无事件、无队列、无消费者、无 DLQ（`contracts/events.yaml` 为空）。

## 外部副作用补偿

- 无外部消息、邮件、通知、第三方写入或支付类副作用，不需要补偿事务。
- 分享链接与收藏数据不做清理：隐藏分类的详情与收藏数据始终保留，回滚后原样可用。

## 回滚后验证

1. 公开配置接口返回 DEFAULT（`revision` 已递增、`updatedAt` 更新）；后台展示一致。
2. 小程序体验版/真机进入首页只显示「粗门溜车」，列表正常、吸顶条不空。
3. 隐藏场景列表接口返回空数组，详情与分享链接返回 200。
4. 日志中无持续 `scene_tabs_config_invalid` / 5xx 激增。
5. 记录回滚 SHA、时间、执行人、命令与退出码到 `evidence/`；未执行项标记 `not-run`。
