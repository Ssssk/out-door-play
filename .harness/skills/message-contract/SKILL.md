# RabbitMQ 消息契约

## 触发条件

- 新增或修改事件、命令、exchange、queue、binding、routing key 或消费者。
- 改变消息字段、投递顺序、重试、DLQ、幂等或重放行为。
- 同步流程准备异步化，或数据库提交后需要可靠发布事件。

## 不适用场景

- 普通 HTTP API 契约；使用 api-contract-design。
- 仅在进程内发布、不跨可靠性边界的通知。
- 业务一致性和失败补偿仍未确定。

## 前置 Gate

- 需求和设计 Gate 已通过，异步边界、最终一致性和用户可见行为明确。
- 生产者、消费者 Owner 和兼容窗口已识别。
- 关键数据变化的事务与 Outbox 策略已批准。

## 必读上下文

1. `rules/09-RabbitMQ消息规范.md`、后端、安全、测试和发布 Rules。
2. `wiki/08-消息模型.md`、`wiki/12-可观测性模型.md`。
3. 当前 `contracts/events.yaml`、生产者、消费者、拓扑配置和 Outbox 实现。
4. 需求、AC、设计、影响分析、错误/补偿策略及历史 MQ 事故。

## 输入

- 业务事件含义、发生时点、数据所有者和消费者需求。
- 吞吐、延迟、顺序、重复容忍、保留、重放和故障恢复目标。
- 新旧消费者部署顺序和 schema 兼容要求。

## 执行步骤

1. 判断消息是事实事件还是请求命令，使用已发生事实命名事件。
2. 定义统一信封：eventId、eventType、schemaVersion、occurredAt、producer、traceId、payload。
3. 定义 payload 字段、必填、类型、枚举、单位、敏感级别与所有权。
4. 定义 exchange 类型、durable、routing key、queue、binding、quorum/classic 选择与理由。
5. 定义 publisher confirm、mandatory/unroutable 处理以及数据库事件的 Outbox 流程。
6. 定义消费者并发、prefetch、超时、手动 ACK/NACK 和优雅停机行为。
7. 选择幂等键、幂等存储、原子边界、保留周期和重复成功响应。
8. 定义可重试错误、不可重试错误、次数、指数退避、抖动和总时限。
9. 定义 DLX/DLQ、告警、查看权限、修复、重放顺序和审计。
10. 分析重复、乱序、延迟、丢失连接、毒消息、消费者崩溃和积压场景。
11. 定义 schema 演进：新增可选字段、版本路由、双发/双读与废弃窗口。
12. 更新事件契约、拓扑说明、测试矩阵、指标和发布顺序。

## 技术约束

- 默认只保证至少一次投递，禁止宣称端到端 exactly-once。
- 关键业务事件必须与业务数据通过 Outbox 等方式建立可靠边界。
- eventId 全局唯一且重放保持不变；correlation/traceId 不得替代幂等键。
- 消费者只有在业务副作用与幂等状态成功后 ACK；进程收到消息不代表成功。
- 无限重试、零延迟热循环和所有错误一律重试均禁止。
- 消息中避免携带不必要敏感数据和巨大对象；消费者按 ID 回查需考虑一致性和可用性。
- 同一 queue 内消费者竞争，不用于广播；广播消费者使用独立 queue。
- 依赖严格全局顺序时必须重新评估模型，RabbitMQ 不提供任意并发下的全局顺序。

## 产物

- `contracts/events.yaml` 事件 schema 和版本定义。
- exchange/queue/binding、Outbox、幂等、重试、DLQ 与重放方案。
- 生产者/消费者兼容矩阵、指标告警和发布顺序。
- 重复、乱序、毒消息、停机和重放测试用例。

## 验证与证据

- schema 校验通过，生产者序列化与消费者反序列化一致。
- 使用真实 RabbitMQ 验证 confirm、unroutable、ACK/NACK、重试、DLQ 和重放。
- 重复投递不会重复产生业务副作用；消费者崩溃后消息可恢复。
- 新旧 schema 在滚动发布窗口内互操作，未知可选字段不导致失败。

## 停止与升级条件

- 无法定义幂等业务键、补偿责任或最终一致性用户体验。
- 需要严格全局顺序、跨库原子提交或零丢失但现有架构无法满足。
- DLQ 无 Owner、无告警或无安全重放流程。
- 变更会破坏未知消费者或要求无窗口删除旧字段。

## 禁止事项

- 不发布数据库尚未提交的数据事实。
- 不在消费者失败时吞异常后 ACK，不通过自动 requeue 制造无限循环。
- 不复用同一事件名表达不同业务语义。
- 不把单次成功演示当作可靠性证据。

## 完成定义

事件语义、schema、拓扑、可靠发布、消费幂等、重试、DLQ、重放、兼容与观测完整；失败场景经过验证；生产者和消费者可依据契约独立实现。
