# 集成、E2E 与回归验证

## 触发条件

- 实现任务完成，准备验证基础设施协作和端到端业务结果。
- 变更涉及 API、事务、缓存、消息、迁移、跨端交互或核心用户路径。
- Bugfix、依赖升级或重构需要影响面回归。

## 不适用场景

- 仅验证纯函数或隔离业务规则；使用 unit-test-write。
- 在未授权生产环境创建测试数据或执行破坏性验证。
- 实现仍有已知编译、单元测试或契约错误。

## 前置 Gate

- Change 状态为 `implementing` 或 `verifying`，实现 Gate 的基础静态检查已通过。
- `verification/test-plan.md` 和追踪矩阵已覆盖所有 FR/AC。
- 隔离环境、测试账号、种子数据和基础设施版本可识别且可清理。

## 必读上下文

1. 当前 Change 全部需求、AC、设计、影响分析、任务和契约。
2. 测试、安全、MySQL、Redis、RabbitMQ 和发布 Rules。
3. 目标平台矩阵、部署拓扑、历史缺陷与不稳定测试记录。
4. 相关知识中的事故、回归范围和运行手册。

## 输入

- 测试计划、测试 ID、FR/AC 追踪、环境和制品版本。
- OpenAPI、错误码、事件 schema、迁移与回滚方案。
- 影响分析产生的直接、上下游和核心回归范围。

## 执行步骤

1. 固定代码 SHA、依赖锁、配置版本、MySQL/Redis/RabbitMQ 版本和目标端。
2. 创建隔离 namespace/database/vhost 与确定性种子数据，确认不会连接生产。
3. 先执行数据库 migration，并验证新旧应用兼容及必要 revert/前向修复。
4. 执行 API 契约测试：校验、权限、状态码、错误码、幂等、冲突和兼容。
5. 执行 MySQL 集成：提交、回滚、约束、锁、并发和关键查询计划。
6. 执行 Redis 集成：命中、失效、TTL、缓存重建、穿透和不可用降级。
7. 执行 RabbitMQ 集成：confirm、重复、乱序、重试、DLQ、重放与消费者崩溃。
8. 执行 uni-app 关键路径：页面操作、请求、服务端副作用和最终用户可见结果。
9. 对小程序/App 专属登录、支付、权限、上传等能力在目标端或真机验证。
10. 按影响分析执行直接功能、上下游、共享能力、历史缺陷和核心链路回归。
11. 前端变化执行 accessibility 验证；有性能 NFR 时执行容量、峰值与耐久测试。
12. 工程验证完成后把冻结候选制品交给 `product-uat`，不得由测试人员代替产品签收。
13. 对失败分类为产品缺陷、环境故障、测试缺陷或不稳定，并保留首次失败证据。
12. 修复后重跑失败用例、相关影响集和规定全量集，不用单次重跑掩盖问题。
13. 更新追踪矩阵、evidence、缺陷和残余风险，准备验证 Gate。

## 技术约束

- 集成测试使用真实或容器化 MySQL/Redis/RabbitMQ，不以简单内存 Fake 证明基础设施语义。
- 测试数据可重复创建、可清理、无生产敏感数据；并行测试具有隔离标识。
- 不用固定 sleep 等待异步结果；使用轮询条件、超时和最终一致性窗口。
- E2E 断言用户可见结果和持久化/事件副作用，不只断言 HTTP 200。
- 回归集必须来自影响分析，不因时间压力静默缩小；缩减需要书面风险接受。
- H5 证据不能替代需求指定的小程序/App 目标端证据。

## 产物

- 集成、契约、E2E 和回归测试代码/执行记录。
- accessibility、performance 和 UAT 的独立结论或明确 not-required 决策。
- 更新的 `verification/test-plan.md`、`traceability-matrix.md` 和 evidence。
- 环境、SHA、数据版本、命令、退出码、报告和失败分类。
- 未解决缺陷、测试不稳定项和残余风险清单。

## 验证与证据

- 每个 FR/AC 至少有通过证据或明确未通过结论，不允许空白。
- 报告能定位到代码 SHA、环境和制品，不复用旧版本结果。
- 对失败测试保留日志、requestId/traceId、数据库/缓存/消息状态和截图等证据。
- 重复运行核心用例结果稳定，测试结束后无残留消息、连接和脏数据。

## 停止与升级条件

- 环境可能指向生产或无法确认隔离边界。
- 契约、迁移、事件 schema 与实现不一致。
- 出现数据损坏、无法清理副作用、P0/P1 安全问题或系统性不稳定。
- 关键目标端、第三方沙箱或基础设施不可用导致无法形成可信证据。

## 禁止事项

- 不反复重跑直到偶然绿色，不删除失败用例或降低断言。
- 不使用生产 Token、真实用户数据或未授权第三方账户。
- 不把 Mock、截图或人工口述当作数据库/MQ 可靠性证明。
- 不自行将验证 Gate 标记为通过。

## 完成定义

契约、基础设施、关键用户链路、影响面和核心回归均按计划执行；结果与 FR/AC 双向可追踪；失败有分类和处置；证据绑定当前 SHA 与环境；验证 Gate 可由独立 Reviewer 判定。
