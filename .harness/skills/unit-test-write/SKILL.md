# 单元测试编写

## 触发条件

- 新增或修改业务规则、状态转换、纯函数、组件交互、store、composable 或应用用例。
- 修复缺陷需要先固定复现并建立防回归测试。
- 重构需要证明外部行为不变。

## 不适用场景

- 验证 MySQL 事务、Redis TTL、RabbitMQ ACK 等真实基础设施语义。
- 只追求覆盖率而没有可观察行为。
- 需求和设计仍存在关键歧义。

## 前置 Gate

- 对应 FR/AC、预期行为和任务边界明确。
- 确认测试层级，不能用大量 Mock 伪装集成行为。
- Bugfix 已保存修复前可复现证据。

## 必读上下文

1. 当前需求、AC、设计、测试计划和追踪矩阵。
2. `rules/10-测试与质量门禁.md` 及前端/后端编码规则。
3. 被测代码公开行为、邻近测试、测试工具配置和历史缺陷知识。

## 输入

- 被测单元的输入、输出、不变量、错误和副作用端口。
- 边界值、状态转换、权限、并发决策与历史失败样本。
- 项目现有测试框架、命令和 fixture 约定。

## 执行步骤

1. 从 FR/AC 和风险提取行为清单，按正常、边界、失败和历史缺陷排序。
2. 选择真正可隔离的单元；若核心断言依赖真实基础设施，转交集成测试。
3. 先为 Bug 写会失败的最小测试，确认失败原因与缺陷一致。
4. 使用 GIVEN/WHEN/THEN 命名，测试一个明确行为，避免把多个失败原因混在一起。
5. 构造最小且可读的数据 builder，显式覆盖零、空、最大值、非法枚举和状态冲突。
6. 仅在架构端口 Mock Repository、Clock、ID、HTTP 或消息 Publisher。
7. 时间、随机数、UUID 和时区通过可控提供者固定；不得依赖当前机器环境。
8. 前端验证 DOM 可观察状态、事件、store 结果和异步竞态，不断言 Vue 内部实现。
9. 后端验证领域结果、持久化意图、错误类型和业务事件，不只验证调用次数。
10. 运行目标测试、受影响测试和完整单元套件，记录命令与退出码。
11. 更新追踪矩阵，将测试 ID 关联 FR/AC 和证据位置。

## 技术约束

- 测试独立、可重复、无顺序依赖，不共享可变全局数据。
- 禁止真实网络、真实生产资源、非固定当前时间和无界等待。
- Snapshot 只用于稳定且可审查结构，不用大 Snapshot 隐藏业务断言。
- Mock 返回必须符合真实契约；对复杂第三方行为优先使用契约或集成测试。
- 异步测试必须等待真实完成条件，不使用任意 sleep 消除竞态。
- 覆盖率是信号而非 Gate 的唯一依据；新增关键分支必须有风险匹配测试。

## 产物

- 单元测试代码、必要 builder/fake 和最小测试辅助工具。
- 测试 ID、FR/AC 映射和更新后的追踪矩阵。
- 修复前失败、修复后通过及完整套件结果证据。

## 验证与证据

- 同一提交重复运行结果一致，可单独执行也可并行执行。
- 有意恢复缺陷或破坏业务规则时测试应失败，证明断言有效。
- 命令、环境、提交 SHA、开始结束时间、退出码和报告路径已记录。
- 无 `.only`、跳过、静默 catch 或因测试方便而弱化生产代码。

## 停止与升级条件

- 预期行为不明确或测试与 AC 冲突。
- 需要 Mock 大部分系统才能让测试运行，表明层级或设计不合理。
- 发现基础设施语义只能由真实 MySQL/Redis/RabbitMQ 验证。
- 测试持续不稳定且无法定位环境或竞态原因。

## 禁止事项

- 不为通过测试修改验收标准，不删除失败测试。
- 不只断言函数被调用而不验证业务结果。
- 不把手写假的成功结果当作外部系统正确性的证明。
- 不伪造执行输出或把未运行标记为通过。

## 完成定义

关键规则、边界、失败和历史缺陷均有确定性单元测试；测试与 FR/AC 可追踪；目标与完整单元套件通过并有真实证据；需要基础设施验证的部分已明确转交。
