# 全栈安全评审

## 触发条件

- 涉及登录、权限、支付、个人信息、上传、外部 URL、管理操作或数据导出。
- 新增 API、第三方依赖、Redis/MQ 通道、Secret、基础设施权限或公开入口。
- 中高风险 Change、发布前安全 Gate 或事故后的防复发评审。

## 不适用场景

- 未经授权对生产或外部系统主动扫描、爆破或利用。
- 代替法律、合规或渗透测试机构给出正式认证。
- 安全问题修复编码；本 Skill 默认只读评审。

## 前置 Gate

- 需求、数据分类、角色权限和设计至少达到可评审状态。
- 审查范围、环境和允许的验证方式明确。
- 需要主动测试时已获得目标、时间和方法的明确授权。

## 必读上下文

1. `rules/11-安全与隐私规范.md` 及 API、前后端、数据、MQ、发布 Rules。
2. 权限、接口、数据、错误码、消息、部署与观测 Wiki。
3. Change 需求、AC、设计、影响分析、契约、diff 和测试计划。
4. 依赖锁文件、配置 schema、CI、容器和 Secret 引用方式。
5. 历史安全事故、反模式和已接受风险。

## 输入

- 数据流、信任边界、主体、资产、入口、外部依赖和高影响操作。
- 目标平台、认证机制、会话生命周期、权限模型和数据分类。
- 审查环境、制品 SHA、允许的测试权限与限制。

## 执行步骤

1. 绘制从 uni-app 到 API、MySQL、Redis、RabbitMQ、对象存储和第三方的数据流。
2. 枚举匿名、普通用户、管理员、服务账户、消费者和攻击者能力。
3. 对每个 API 检查认证、对象级/功能级授权、租户隔离、输入白名单和限流。
4. 检查 SQL/命令/模板/日志注入、SSRF、路径穿越、开放重定向和反序列化。
5. 检查上传扩展名、MIME、大小、内容、文件名、存储权限、病毒扫描和下载响应头。
6. 检查 Token 存储、刷新、撤销、过期、重放、CSRF/跨域和小程序登录凭证交换。
7. 检查敏感数据最小化、传输/静态加密、脱敏、日志、缓存、消息和保留删除。
8. 检查 Redis Key 越权、未认证暴露、危险命令和敏感值 TTL。
9. 检查 RabbitMQ vhost/用户最小权限、消息重放、伪造、毒消息和敏感 payload。
10. 检查依赖漏洞、锁文件、安装脚本、镜像来源、Secret 注入和 CI 权限。
11. 对依赖、CI、镜像或制品变化执行 `supply-chain-security`，核对 SBOM 与最终 digest。
12. 按 P0/P1/P2/P3 记录条件、影响、证据、修复建议、Owner 和残余风险。
12. 将安全 AC 映射到自动化或经授权人工验证，更新安全评审文件。

## 技术约束

- NestJS Guard 负责认证，显式 Policy/Decorator 负责授权；只校验登录不等于资源授权。
- ValidationPipe 白名单不替代领域级权限和业务规则校验。
- 不向 uni-app 打包服务端 Secret；长期敏感凭证不得存入不安全前端存储。
- 日志、监控、错误响应、Redis 和 RabbitMQ 不保存不必要的密码、Token、证件或完整支付数据。
- 出站 HTTP 使用协议/域名允许列表、DNS/IP 防护、超时、大小限制和重定向限制。
- 密码使用成熟自适应哈希；签名、加密和随机数不得自创算法。

## 产物

- `verification/security-review.md` 威胁、发现、证据、修复和残余风险。
- `security/supply-chain-review.md`、SBOM、例外与到期记录。
- 安全测试项及 FR/AC 追踪关系。
- P0/P1 阻塞项、P2/P3 后续项和风险接受记录。

## 验证与证据

- 每个信任边界和高影响操作都有审查结论。
- 权限测试至少覆盖未登录、低权限、他人资源、跨租户和管理员边界。
- 静态检查、依赖扫描和经授权动态测试绑定当前 SHA 和环境。
- 修复后重新验证原始攻击条件，而不是只阅读代码。

## 停止与升级条件

- 发现可被利用的 P0/P1、密钥泄漏、越权、注入或大规模数据暴露。
- 验证需要超出授权的生产扫描、真实支付或第三方账户操作。
- 数据分类、合规要求或风险接受人不明确。
- 无法隔离测试环境或测试可能影响其他用户。

## 禁止事项

- 不公开可利用细节给无关人员，不在证据中复制真实 Secret。
- 不把无发现写成“绝对安全”。
- 不未经授权执行破坏性 payload、爆破、扫描或生产利用。
- 不由实现者独自接受自己的 P0/P1 风险。

## 完成定义

安全范围、威胁和证据完整；认证授权、输入、数据、客户端、基础设施和供应链均已检查；P0/P1 已阻塞或修复并复验；残余风险有明确 Owner 和批准状态。
