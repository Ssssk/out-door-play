# MySQL 与 TypeORM 数据迁移

## 触发条件

- 新增、修改、重命名或删除表、列、索引、约束、枚举或关系。
- 需要历史数据回填、纠正、拆分、合并或格式转换。
- TypeORM Entity 与数据库 schema 需要受控演进。

## 不适用场景

- 仅修改查询逻辑且 schema 和数据不变化。
- 未经批准直接在生产执行临时 SQL。
- 用 ORM `synchronize` 替代正式迁移。

## 前置 Gate

- 需求和设计 Gate 已通过，数据 Owner、口径和保留要求明确。
- 影响分析包含数据规模、读写调用方、报表、任务和旧应用版本。
- 不可逆操作必须有明确备份、恢复或前向修复批准。

## 必读上下文

1. `rules/07-MySQL与数据迁移规范.md`、发布与测试 Rules。
2. `wiki/06-数据模型.md`、`wiki/11-部署拓扑.md`。
3. 当前 Entity、Repository、Migration、索引、查询和数据库版本。
4. Change 设计、影响分析、`backend/migration-plan.md` 和发布/回滚计划。
5. 历史迁移事故、锁表问题和相关知识记录。

## 输入

- 目标 schema、业务不变量、数据口径和兼容窗口。
- 当前/预计行数、增长率、读写 QPS、表大小和可用维护窗口。
- 应用发布顺序、备份能力和可接受停机时间。

## 执行步骤

1. 记录当前 schema、索引、行数、数据分布、数据库版本和典型查询。
2. 分类变更为 metadata-only、online-capable、blocking、backfill 或 destructive。
3. 设计新旧应用可共存的 expand → migrate → contract 阶段。
4. 编写版本化 TypeORM Migration，明确 `up` 和可行的 `down`；不可逆时解释原因。
5. 新增非空列优先经历可空/默认、回填、验证、再加约束阶段。
6. 大表索引和 DDL 评估锁、临时空间、复制延迟、执行时间与在线能力。
7. 数据回填按主键范围或稳定游标分批，支持断点续跑、限速、幂等和审计。
8. 编写迁移前检查、迁移后行数/空值/唯一性/校验和/抽样验证 SQL。
9. 定义部署顺序：兼容应用、schema、回填、切流、收缩旧结构。
10. 定义失败阈值、暂停、回滚、恢复和前向修复路径。
11. 在隔离环境基于接近真实规模的数据执行 upgrade、兼容验证和可行 revert。
12. 保存命令、版本、数据规模、开始结束时间、锁等待、结果和制品校验值。

## 技术约束

- 生产禁止 `synchronize: true`，所有 schema 变更必须版本化且可审计。
- Migration 不依赖应用运行时业务服务、Redis、MQ 或外部 HTTP。
- MySQL DDL 能否在线必须按实际版本、引擎和语句确认，不凭经验假设。
- 大表禁止单事务无界更新；批次必须可重入并避免长期持锁。
- 新索引必须说明服务的查询及选择性；删除索引前确认无隐藏调用方。
- Decimal 精度、字符集、排序规则、时区、JSON 和 bigint 映射必须显式核对。
- 数据删除、脱敏和修复保留审计，验证结果不得包含未脱敏敏感数据。

## 产物

- TypeORM Migration 文件及必要回填程序。
- `backend/migration-plan.md`：规模、风险、顺序、校验、恢复和 Owner。
- 迁移前后验证 SQL、执行记录和数据质量结果。
- 发布/回滚计划中的数据库步骤与停止阈值。

## 验证与证据

- 空库和现有版本库均能执行 upgrade；可逆迁移验证 down 后再 upgrade。
- 新旧应用版本在兼容窗口内都能读写，不因列缺失或语义变化失败。
- 约束、索引、数据数量、异常值、查询计划和关键性能满足设计。
- 失败注入验证批次可恢复、重复执行不重复修改数据。

## 停止与升级条件

- 无法获得真实规模、数据库版本、备份状态或恢复时间目标。
- DDL 可能长时间锁表、磁盘不足、影响复制或无法在线执行。
- 数据转换规则、异常数据处理或删除授权不明确。
- 操作目标是生产且尚无明确授权和发布 Gate。

## 禁止事项

- 不直接修改生产，不在本 Skill 中推断生产授权。
- 不用一个巨大事务回填全表，不用 offset 分页处理持续变化数据。
- 不将无法回滚写成“可回滚”，不把未执行计划写成证据。
- 不在同一发布中无兼容窗口地重命名或删除仍被读取的字段。

## 完成定义

迁移脚本、兼容顺序、规模/锁风险、回填、校验和恢复路径完整；隔离环境演练通过并有真实证据；发布人员可以按计划执行且知道何时停止。
