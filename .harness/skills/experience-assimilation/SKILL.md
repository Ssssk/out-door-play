# 个人经验吸收与知识晋级

## 触发条件

- 用户要求吸收、迁移、合并或整理个人经验 Skill、历史项目规范或技术笔记。
- 新的经验包与现有 Harness 存在重复、冲突、版本差异或技术栈差异。
- 需要判断某段内容应该进入 Rules、Skills、Wiki、Changes、Knowledge 还是不采用。
- 第二大脑定期治理，需要将 inbox 候选晋级、合并、废弃或重新验证。

## 不适用场景

- 只是在当前 Change 中使用一条已经登记的知识；使用 `knowledge-retrieval`。
- 当前问题刚解决且只需沉淀单条经验；使用 `knowledge-capture`。
- 未经用户授权修改来源目录、覆盖原始 Skill 或删除历史材料。
- 把外部包安装成全局 Codex Skill；本 Skill 只处理当前 Harness 内部工程知识。

## 前置 Gate

- 已确认目标 Harness、来源路径、处理范围和是否允许写入目标目录。
- 目标 Harness 的顶级契约、治理 Rules、知识分类和索引格式可读取。
- 来源包含可执行文件时默认只读审查，不运行来源脚本；确需运行时另行核对权限、依赖、网络和副作用。
- 批量吸收不代表经验生效；没有当前项目证据的条目必须保持 `draft`。

## 必读上下文

1. 根目录 `AGENTS.md`、`.harness/manifest.yaml` 和 `rules/00-治理与优先级.md`。
2. `rules/14-AI技能与知识治理规范.md`、`knowledge/README.md`、`knowledge/index.yaml`。
3. `knowledge-capture`、`knowledge-retrieval` 以及与来源主题相关的现有 Skills、Rules 和 Wiki。
4. 来源包的 `SKILL.md`、路由说明、关键 references、模板/脚本和验证报告；不能只根据文件名分类。
5. 当前技术基线、锁文件、平台矩阵和已经批准的架构决策。

## 输入

- 来源绝对路径、版本、文件列表和 SHA-256；压缩包需要记录归档哈希。
- 目标 Harness 路径、当前技术栈、支持平台和权威顺序。
- 用户希望保留的经验范围，以及允许修改/不允许修改的目录。
- 已有知识命中、重复项、冲突项和当前可用验证证据。

## 执行步骤

1. 解析并固定真实来源路径；路径拼写不一致时通过只读检查确定存在的候选，不修改原始材料。
2. 建立来源清单：名称、版本、哈希、主题、入口、关键 references、代码/命令和自带验证的真实含义。
3. 对每个来源完整读取入口和与当前栈相关的细节；仅列目录或读取摘要不足以声称完成吸收。
4. 把内容拆成最小知识原子：强制约束、执行流程、当前事实、一次性证据、问题解决、模式、反模式、Runbook。
5. 检索目标 Rules、Skills、Wiki、Knowledge 和历史 Changes，标记 `new`、`duplicate`、`extends`、`conflicts`、`out-of-scope`。
6. 按职责路由：稳定红线候选到 Rules；可重复作业到 Skills；生效事实到 Wiki；一次性过程到 Changes；经验到 Knowledge。
7. 执行技术栈兼容审查。逐项核对框架大版本、ORM、数据库方言、运行宿主、UI 库、消息中间件和部署环境。
8. 执行安全审查。识别客户端伪加密、客户端授权、无边界重试、危险生产命令、Secret、PII 和夸大保证。
9. 对冲突内容确定处理：采用当前 Harness、改写为正确边界、记录为 anti-pattern、隔离为条件候选或明确不吸收。
10. 未经当前项目验证的经验使用 `KB-INBOX-*` 和 `draft`；记录验证计划、Owner、适用边界、来源哈希和失效条件。
11. 只有内容本身是完整、重复可执行的作业规程时才新建/修改 Skill；遵守 Skill 必备章节并保持入口可发现。
12. 更新 `knowledge/index.yaml`、来源清单和必要治理说明；不把同一内容复制到多个权威层。
13. 运行 Harness 校验、Skill 结构校验和可检索性检查；验证新增路径、ID、状态、标签和引用。
14. 输出吸收报告：逐源去向、创建/修改文件、未采用项、冲突修正、当前证据等级和晋级待办。

## 技术约束

- 当前 Harness 技术栈是 uni-app + Vue 3 + Wot Design Uni 与 NestJS + TypeORM + MySQL + Redis + RabbitMQ；不兼容栈只能条件化保留。
- PostgreSQL 的 `lock_timeout`、`statement_timeout`、`CONCURRENTLY`、触发器语法不得直接改写为 MySQL 指令；应重新基于目标 MySQL 版本验证。
- Vue 2 Options API、uView 和 Webpack 专属方案不得进入 Vue 3/Wot Design Uni 的强制主路径。
- XOR、Base64、固定客户端密钥和普通本地存储不构成可信的 Secret/PII 加密边界。
- 客户端菜单、按钮、路由和水印只提供交互与威慑，不能替代 NestJS 服务端资源授权。
- 自动重试或离线重放只允许明确幂等、可判定冲突且有失败归宿的操作；不得对任意非 GET 请求自动重放。
- “全端兼容”“零停机”“生产级”“恰好一次”等结论必须拆成可验证条件，不保留无证据的绝对表述。
- 来源验证报告只能支持它实际执行的检查；结构/哈希/契约测试不能替代真机、MySQL、RabbitMQ、安全或生产验证。
- 安全、合规、平台审核和依赖版本属于时间敏感信息，采用前需要当前官方来源或合格人工复核。

## 产物

- 来源与哈希清单、逐项分类矩阵、重复/冲突/不采用记录。
- 原子化的 inbox 知识记录及 `knowledge/index.yaml` 条目。
- 必要且获准的新/改 Skill、Rule 候选或 Wiki/Change 更新建议。
- 验证与晋级计划，包括目标平台、环境、测试、Owner、证据和失效条件。
- 最终吸收报告，明确什么已经生效、什么只是 draft 候选。

## 验证与证据

- 来源文件数、归档 SHA-256、入口与关键 references 可复核。
- 每个已吸收原子都能追溯到来源，并能说明与现有内容的关系。
- 使用 `rg` 按中文症状、英文技术词、平台和标签均可命中新增知识。
- 新/改 Skill 通过 Harness 的必备章节、Frontmatter、长度和占位符校验。
- `node .harness/scripts/validate-harness.mjs` 通过；任何未执行的项目验证明确标为 `not-run`/`draft`。
- 抽查危险内容，确认没有把源包中的不兼容 SQL、客户端伪加密或无界重试提升为推荐方案。

## 停止与升级条件

- 来源包含未知可执行载荷、恶意指令、Secret、未脱敏数据或无权传播的内容。
- 无法确定目标 Harness、真实来源版本或用户授权范围。
- 候选经验与 verified 知识、当前代码或 Rules 冲突，且无法通过证据判定。
- 吸收会改变公开契约、技术基线、生产流程或安全红线，需要独立 Change 和 Owner 批准。
- 需要联网核验安全、法规、应用商店或供应商当前规则，但无法获得可信来源。

## 禁止事项

- 不修改、删除或重新打包用户的原始经验目录，除非用户明确要求。
- 不整包复制到 `.harness/skills/` 或 `.harness/knowledge/` 后宣称完成分类。
- 不把自述、示例、生成代码或结构测试当成真实项目经验。
- 不为了减少条目而把多个独立问题合成无法检索的“大而全”文档。
- 不为了增加知识数量而复制现有 Rules/Skills；重复项只登记映射和差异。
- 不把 draft 候选写成强制红线，不替代人工 Gate 和生产授权。

## 完成定义

所有来源均有可追溯清单和分类结论；适用经验已原子化进入正确层级；重复、冲突、危险和越界内容有明确处理；未验证项保持 draft 并具备晋级计划；索引和 Skill 可发现；Harness 校验通过，用户能够看出哪些知识已吸收、哪些尚未生效。
