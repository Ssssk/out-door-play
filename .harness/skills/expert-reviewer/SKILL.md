# 独立专家评审

## 触发条件

- 实现与验证声称完成，需要独立判断验证 Gate 或发布 Gate。
- 高风险修复、数据库迁移、API 破坏性变化或安全边界改变。
- 修复评审问题后需要重新验收。

## 不适用场景

- Reviewer 同时是主要实现者或测试证据唯一提供者。
- 评审过程中直接修改代码、测试或契约。
- 用风格偏好阻塞不违反规则且满足契约的实现。

## 前置 Gate

- Reviewer 使用 fresh context、只读权限，身份和评审范围已记录。
- 当前 SHA、Change 状态、diff、测试及发布证据可访问。
- 默认结论为失败，只有证据证明全部条件满足后才通过。

## 必读上下文

1. `manifest.yaml`、全部适用 Rules 和当前系统 Wiki。
2. Change 请求、需求、AC、影响、设计、任务、契约、测试、发布和回滚文件。
3. 完整 diff、构建制品、测试报告、迁移演练和安全评审。
4. 引用的知识、ADR、事故与残余风险，但不把实现者总结当作独立证据。

## 输入

- 待评审 SHA/PR、Change ID、目标 Gate 和批准范围。
- 可复核命令、日志、报告、制品、环境及人工审批。
- 已知问题、风险接受和上一轮评审发现。

## 执行步骤

1. 核对 Change 身份、状态、审批和 diff 范围，发现范围漂移立即记录。
2. 从 FR/NFR/AC 反向追踪到设计、TASK、代码、测试和 evidence。
3. 审查 uni-app 分层、跨端差异、异步状态、错误提示和敏感信息。
4. 审查 NestJS 模块边界、DTO、权限、事务、并发、错误和观测。
5. 审查 OpenAPI/错误码与实现，验证旧客户端和破坏性变化策略。
6. 审查 MySQL migration、规模、锁、兼容、回填、校验和恢复。
7. 审查 Redis Key/TTL/一致性/降级以及 RabbitMQ Outbox/幂等/重试/DLQ。
8. 审查测试层级、失败路径、回归范围、执行真实性和不稳定处理。
9. 审查安全、隐私、依赖、配置、Secret、日志和最小权限。
10. 审查发布顺序、功能开关、监控、灰度阈值、回滚和责任人。
11. 审查原始需求基线、UI/UX、accessibility、产品 UAT、供应链安全和运营就绪证据。
12. 对照 `gate-decisions.json` 检查 Gate 状态、审批人、时间和证据路径。
13. 必要时以只读方式复运行可重复校验，记录环境和结果。
12. 按 P0/P1/P2/P3 输出发现，包含条件、影响、证据位置、复现和建议。
13. 给出 `pass` 或 `reject`；列明 Gate 条件和需重新评审的范围。

## 技术约束

- P0：正在或极可能导致重大安全、数据、资金或生产事故；立即阻塞。
- P1：核心契约错误、数据风险、权限绕过、不可回滚或关键测试缺失；阻塞 Gate。
- P2：重要可靠性、维护性或覆盖缺陷；需计划修复并由 Gate Owner 决定。
- P3：非阻塞改进建议，不得与强制规则混淆。
- 证据必须绑定 SHA、环境和时间；截图不能证明不可见的数据/消息正确性。
- “没有发现”不等于证明不存在；结论仅覆盖声明范围和证据。

## 产物

- 独立评审报告、发现列表、严重度、证据和复现步骤。
- FR/AC/设计/TASK/测试/evidence 追踪断点清单。
- 来源基线、Gate 决策和机器 Evidence 的一致性问题。
- Gate 结论、通过条件、残余风险和复审范围。

## 验证与证据

- 抽样重新执行关键命令，核对报告与当前 SHA 一致。
- 检查测试是否能在故意破坏实现时失败，避免空洞断言。
- 检查发布和迁移证据是已发生事实还是仅计划。
- 所有 P0/P1 均有明确状态，不能仅在正文中提及而结论仍通过。

## 停止与升级条件

- Reviewer 不独立、需要写权限或无法获得完整 diff/证据。
- Change 范围与实现严重不符，无法在当前评审范围内判断。
- 发现 P0/P1、安全泄漏或生产证据异常。
- 关键证据无法复现、来源不明或疑似伪造。

## 禁止事项

- Reviewer 不修改代码、测试和契约，不批准自己的修复。
- 不以实现者口头解释替代可复核证据。
- 不因截止日期降低严重度或忽略 Gate 条件。
- 不把个人风格偏好包装成 P0/P1。

## 完成定义

评审范围、方法、发现、证据和结论可由第三方复核；全部 P0/P1 已阻塞或关闭；追踪完整；Reviewer 保持独立；Gate Owner 获得明确可执行的通过或拒绝依据。
