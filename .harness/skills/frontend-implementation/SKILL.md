# uni-app 前端实现

## 触发条件

- 已批准任务需要新增或修改页面、组件、状态、请求、路由或平台能力。
- Bugfix 已具备复现条件、正确行为和防回归 AC。
- 重构已定义页面行为、API 和跨端兼容不变量。

## 不适用场景

- 需求或设计 Gate 未通过。
- API、交互、目标平台或权限行为尚未确定。
- 需要修改服务端业务规则、生产配置或发布状态。

## 前置 Gate

- Change 状态为 `approved` 或 `implementing`。
- TASK 已关联 FR/AC，页面流程、组件设计和 OpenAPI 已批准。
- 已明确 H5、微信小程序、App 等目标端以及真机要求。
- 已检索相似页面、组件、跨端缺陷和历史解决方案。

## 必读上下文

1. 当前 Change 的需求、AC、影响分析、设计、任务、API 和错误码契约。
2. `rules/03-TypeScript与编码规范.md`、`rules/04-前端工程规范.md`、测试和安全 Rules。
3. 前端架构、接口、权限、错误码与目标平台 Wiki。
4. 当前页面、公共组件、Pinia、请求层、路由/分包配置和测试。

## 输入

- 已批准页面流程、组件职责、视觉/交互状态和 API 契约。
- 目标端、最低版本、权限、埋点、性能和可访问性要求。
- 任务边界及可复用 Wot Design Uni 组件。

## 执行步骤

1. 确认 `pages.json` 路由、分包和导航影响，避免无意增加主包体积。
2. 将职责拆为页面编排、业务组件、composable、Pinia store、api client、types 和纯 utils。
3. 使用 `<script setup lang="ts">` 和 Composition API 实现稳定类型，不以 `any` 绕过契约。
4. 优先组合 Wot Design Uni 组件，业务封装表达领域语义，主题使用集中变量。
5. 在 API 层映射请求、响应和错误码；页面不散落 base URL、header 或原始错误处理。
6. 实现 loading、empty、error、permission-denied、disabled、success 和弱网状态。
7. 写请求提供重复提交保护；只有明确幂等且瞬时失败的请求才允许有限重试。
8. 处理页面卸载、快速切换、搜索防抖、旧响应覆盖新状态和取消请求竞态。
9. 会话过期使用单航班刷新；失败后清理会话并阻止无限重放。
10. 平台专属代码集中在 adapter/composable，通过条件编译隔离并提供降级。
11. 添加组件、store、composable 单元测试及关键页面 E2E/人工验证步骤。
12. 执行 lint、类型检查、构建和目标端验证，保存证据并更新 TASK。

## 技术约束

- 页面负责生命周期、路由参数和用例组合；不得直接承载可复用业务规则和请求细节。
- Pinia 只存跨页面状态；短期 UI 状态留在组件，敏感 Token 不持久化到不安全存储。
- Props、Emits、Slots 和公开 composable 返回值必须显式类型化。
- 列表渲染使用稳定业务 key，不以数组索引掩盖更新错误。
- Wot Design Uni 主题通过变量集中维护；禁止散落同义颜色、间距和 z-index 魔法值。
- 不直接使用浏览器 DOM、Node API；确需平台能力时必须隔离并声明支持矩阵。
- 所有用户可触发异步动作必须有防重复、超时、错误反馈和恢复路径。
- 图片、长列表、分包和首屏请求按性能预算处理，避免无界一次性加载。
- 错误提示基于稳定业务错误码，本地化文本不依赖服务端内部 message。

## 产物

- 页面、组件、composable、Pinia、API、types、样式和必要配置变更。
- 页面状态矩阵、目标平台验证记录和交互边界说明。
- 单元/组件/E2E 测试及截图、录屏或日志等辅助证据。
- 更新的 TASK、追踪矩阵和必要 Wiki 候选。

## 验证与证据

- 运行格式、Lint、TypeScript 类型检查、单元测试和目标端构建。
- 对每个 AC 验证成功、空、错误、权限、弱网、重复提交和返回恢复。
- H5 不能替代小程序/App 专属能力证据；按目标矩阵进行真机或对应模拟环境验证。
- 校验页面销毁后不更新失效状态，重复响应不覆盖较新数据。
- 检查包体积、首屏请求、控制台错误、未处理 Promise 和敏感信息。

## 停止与升级条件

- 需要改变 API、错误码、页面流程、需求范围或设计边界。
- Wot 组件无法满足需求且二次封装会改变通用设计体系。
- 平台能力、权限、审核规则或真机环境无法确认。
- 发现服务端缺少幂等、并发或安全保障，前端无法可靠补偿。

## 禁止事项

- 不复制 Wot 基础组件实现来绕开统一主题和行为。
- 不在页面散落重复请求代码、权限判断和错误码字符串。
- 不用 H5 通过证明所有目标端通过。
- 不通过注释、跳过测试或强制类型断言隐藏缺陷。

## 完成定义

页面与组件按批准分层实现；全部交互状态、跨端差异和 API 错误均有处理；目标端构建及相关测试通过并有真实证据；不存在未批准的需求或契约偏差。
